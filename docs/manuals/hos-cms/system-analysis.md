# วิเคราะห์ระบบ HOS-CMS สำหรับคู่มือผู้ใช้

ตรวจเมื่อ 26 พฤศจิกายน 2569 บน `http://localhost:3000` โดยอ่าน source และสำรวจ Chromium/Playwright แบบอ่านอย่างเดียว ไม่มีการกดบันทึก ลบ เผยแพร่ หรือจับภาพสำหรับคู่มือ

## การเข้าใช้และสิทธิ์

- เปิดโปรไฟล์ Chromium เดิมซ้ำแล้วเข้า `/admin` ได้ HTTP 200 พร้อมหน้า Dashboard โดยไม่เข้าสู่ระบบใหม่ จึงยืนยันการใช้ session เดิมซ้ำได้ โปรไฟล์อยู่ที่ `/private/tmp/hos-cms-manual-browser-profile` นอก repository ห้ามนำไป commit หรือเผยแพร่
- Login อยู่ที่ `/login`; มีหน้ารหัส OTP ที่ `/login/otp` และบังคับเปลี่ยนรหัสผ่านใหม่เมื่อบัญชีถูกกำหนดให้เปลี่ยนรหัสผ่าน
- บทบาท `ADMIN` เข้าแผง `/admin` ได้ ส่วน `MEMBER` ถูกเปลี่ยนเส้นทางกลับเว็บไซต์ Public ตาม `src/app/(admin)/admin/layout.tsx` ทั้งสองบทบาทเข้าหน้าโปรไฟล์และความปลอดภัยของตนได้
- หน้าเว็บไซต์และหน้าหน่วยงานรองรับสิทธิ์ `PUBLIC`, `AUTHENTICATED`, `CUSTOM` โดย `CUSTOM` เลือกผู้ใช้หรือหน่วยงานที่ได้รับสิทธิ์ ระบบตรวจสิทธิ์ที่ server ก่อนแสดงหน้า ข่าว เอกสาร และสื่อยังเป็นเนื้อหา Public ตามขอบเขตปัจจุบัน
- ยังไม่ได้ทดสอบด้วยบัญชี `MEMBER` หรือผู้ไม่เข้าสู่ระบบในหน้าเฉพาะสิทธิ์ จึงอ้างอิงพฤติกรรมการป้องกัน route จาก source ไม่อ้างว่าได้ทดสอบทุกบทบาทผ่าน Browser

## เมนูผู้ดูแลที่พบจริง

แถบข้างกำหนดใน `src/components/admin/admin-sidebar.tsx` และตรงกับเมนูที่ Browser แสดง ทุก route ด้านล่างเปิดได้ HTTP 200 ด้วย session ผู้ดูแล ยกเว้นหน้ารายการที่ต้องรอโหลดข้อมูลจึงจะเห็นองค์ประกอบครบ

## ส่วนที่ต้องครอบคลุมในคู่มือ

### เว็บไซต์ Public

หน้าแรก `/` อาจพาไป `/welcome` ตามการตั้งค่าหน้าต้อนรับ; ปุ่มเข้าสู่เว็บไซต์เป็นการนำทาง หน้า Public ที่ตรวจจริง ได้แก่ `/news`, `/units`, `/documents`, `/search`, หน้าเกี่ยวกับองค์กร `/about-us`, `/vision`, `/structure`, หน้าเจ้าหน้าที่ `/officer-service`, `/privacy-policy`, `/cookie-policy` เมนูจริงยังมีลิงก์ที่สร้างจากฐานข้อมูล จึงต้องตรวจเมนูที่เผยแพร่ ณ วันที่จับภาพอีกครั้ง รายการข่าวมีค้นหา/กรองหมวด ปี และหน่วยงาน; หน่วยงานมีค้นหาและหน้ารายละเอียด; เอกสารมีค้นหา/กรองหมวดและปี; ค้นหาทั้งเว็บไซต์มีช่องคำค้น

### บัญชีของฉัน

เมนูบัญชีมีโปรไฟล์, ความปลอดภัย, ทางไป Admin เฉพาะผู้ดูแล และออกจากระบบ โปรไฟล์แก้ข้อมูลและรูปภาพของตน; ความปลอดภัยมีเปลี่ยนรหัสผ่าน, การยืนยันสองขั้นตอน, และออกจากอุปกรณ์อื่น หน้ารหัสกู้บัญชี `/profile/security/recovery` เข้าถึงได้เฉพาะช่วงหลังการสร้างรหัสชุดใหม่ จึงไม่ควรแสดงรหัสจริงในคู่มือ

### Page Builder และเนื้อหา

หน้าแรกและหน้าเว็บไซต์อื่นใช้ Page Builder เดียวกัน มีตั้งค่าหน้า/ชื่อ, เพิ่ม/เรียง/ทำสำเนา/ซ่อน/ลบบล็อก, ย้อนกลับ/ทำซ้ำ, ตัวอย่าง, ร่าง/เผยแพร่ และสิทธิ์เข้าถึง บล็อกที่ source เปิดให้เพิ่ม ได้แก่ แบนเนอร์, หัวข้อ, ข้อความ, รูป, ปุ่ม, การ์ดลิงก์, กลุ่มบริการ, แกลเลอรี, คำกล่าว, วิดีโอ, PDF, ดาวน์โหลด, รายการเอกสาร, ตารางเวลา, FAQ, ตาราง, สถิติ, ขั้นตอนงาน, ช่องทางติดต่อ, แผนที่, เส้นเวลา, ข้อความแจ้งเตือน, เส้นคั่น, ข่าว, แท็บข่าว, แท็บเอกสาร และ iframe รายละเอียดการตั้งค่าบล็อกควรแบ่งเป็นตารางสั้นและตัวอย่างกลุ่มบล็อก เพื่อให้เจ้าหน้าที่อ่านได้ง่าย

ตัวแก้ไขข่าวมีแบบฟอร์มและแบบบล็อก โดยใช้การตั้งค่าบล็อกร่วมกับ Page Builder; หน่วยงานมีแท็บข้อมูลทั่วไป (ข้อมูล/ติดต่อ), เนื้อหา, เมนูบริการแบบกลุ่ม, บุคลากร และการจัดหน้า พร้อมสิทธิ์ของหน้าหน่วยงาน

## ข้อจำกัดและการตรวจต่อเมื่อได้รับอนุมัติ

- การสำรวจครั้งนี้เปิดหน้ารายการ/หน้าสร้าง และอ่าน source แต่ไม่ได้กดปุ่มที่เปลี่ยนข้อมูลหรือทดสอบการบันทึกจริง จึงยังไม่ยืนยันผลหลังบันทึก การเผยแพร่ การลบ การกู้คืน และการนำเข้า Excel ผ่าน Browser
- หน้าที่ต้องมีรายการเดิม เช่น แก้ไขผู้ใช้ ข่าว หน้า หรือหน่วยงาน ตรวจจากลิงก์ที่ปรากฏและ source; รายละเอียดหน้าต่างบางตัวไม่ได้เปิดเพราะอาจมีข้อมูลส่วนบุคคลหรือขั้นตอนยืนยัน
- ยังไม่ได้ทดลอง flow OTP/รหัสกู้บัญชี เพราะอาจเปิดเผยความลับและเปลี่ยนการตั้งค่าความปลอดภัย
- หน้า Public ที่จำกัดสิทธิ์ยังไม่ได้ทดสอบด้วย `MEMBER` หรือผู้เยี่ยมชม
- รายชื่อเมนูและเนื้อหา Public มาจากฐานข้อมูล เปลี่ยนได้ก่อนวันผลิตภาพจริง; ต้องทวนอีกครั้งก่อนบันทึกภาพ
- สคริปต์ `visual-check`/`user-manual` เปิด Browser headless ใหม่เสมอ ไม่รับ persistent profile โดยตรง ระยะทำคู่มือต้องใช้ Session ที่ผู้ใช้อนุญาตผ่าน Playwright persistent context และไม่ใส่ authentication state ใน repository
